# Exercise sets and section reviews: plan for Sections I–XI

This is the plan for the exercise sets and section reviews, approved by Timothy. It follows ITEM-LIST.md (rules 4–8 and 11, and the "Exercise" line of each deck). The sets and reviews are written as they come in Phase 3, section by section, and the table below marks each one WRITTEN with its date; a file still marked as a plan shows its plan screen in the course. As of 20 Oct 2026 the sets and reviews of Sections I to X are written (the Imitation set of X was already written); the review of Section XI is a plan. The question points in the decks are a separate matter: those of Sections I to X are written.

## What exists

- **Data files.** One file for each set and review, `data/exercises/<id>.js`, in the same form as the Section I review `data/exercises/i.review.js`: `ARS.exercises['<id>'] = { … }`. With the reviews added on 17 Oct 2026 there were 29 files; since 18 Oct 2026, when `i.ex.sign` was merged into `i.review`, there are 28: 16 exercise sets and 12 section reviews. `data/exercises/index.js` lists the files (`ARS.exerciseFiles`) and maps each deck to the set opened from its Exercise button (`ARS.deckEx`).
- **In the app.** On the course page, a section review or shared exercise button with a plan now opens a "Coming soon" screen that shows the plan and the empty slots, set by set; a deck with its own set has an "Exercise →" button that opens the same screen. Section I has no exercise set of its own: its one exercise is the written, runnable review `i.review` (six rotating sets).
- **Every section has a review** (Timothy, 17 Oct 2026, REVISION-GUIDE N.4): reviews were added for I, VIII, IX, X, and XI (`i.review`, `viii.review`, `ix.review`, `x.review`, `xi.review`), so there are twelve section reviews in all. XI still has no exercise set of its own.

## The format of a plan file

Each file holds the plan and the stubs:

| Field | Meaning |
|---|---|
| `id`, `kind`, `section`, `title` | stable id (never reused), `exercise` or `review`, section, button title |
| `status` | `plan` until the questions are written |
| `openedFrom` | the button that opens the set (its own button, or a deck's Exercise button) |
| `covers` | the decks covered and, for exercise sets, the cards whose teaching the items draw on |
| `skill` | what the set practices |
| `types` | the item types planned (below) |
| `pool`, `sets`, `rotation` | total slots, slots per fixed set (A, B, C), and the rotation (A, B, C, A, …; the sets are never reordered, but the options of each item are shuffled on display, see the build list; Imitation in fixed order) |
| `balancePerSet` or `groupsPerSet`, `split` | how each set is divided among decks or kinds of item |
| `limit` | the taught-only limit (rule 4) |
| `instr` | the instruction line shown to the student (TODO) |
| `items` | the stubs |

Each stub has `id`, `set`, `deck`, usually `card` (the card it draws on), `type`, sometimes `group`, `lang` (`en` or `la`), or `trope`, and `todo: true`. When an item is written, `todo` is removed and the fields of the Section I draft are added: `prompt`, `options` (four, written in a fixed order but shown shuffled on each visit, with the answer key following the option, not the position), `answer` (0-based), and `explain` (full sentences, shown after "Correct" or "Incorrect," rule 11). Passage stubs (IX.2) hold five question stubs each, tagged reading, explaining, or judging; Imitation stubs hold the work, the selection, the source note (`src`), and the word count from ITEM-LIST.md. The passage itself is the field `text`.

## Item types

| Type | What the student does | How it is checked |
|---|---|---|
| multiple choice (`mc`) | chooses one of four options | the fixed answer |
| multiple choice on a marked word (`mc-marked`) | the same, about a word marked in a sentence or line | the fixed answer |
| identify in the text (`identify`) | clicks the word or syllable asked for (for example, the stressed syllable) | the stored position |
| count (`count`) | types a number (for example, the number of syllables) | exact |
| divide into syllables (`divide`) | types the word with hyphens | exact, against the division taught in II.3 |
| give the form (`form`) | types a Latin or English form | exact, against the form generated from the tables (ITEM-LIST, III.6 and III.9) |
| rewrite (`transform`) | rewrites a sentence (for example, corrects a solecism) | against a short list of accepted answers |
| parse and construe (`analysis`) | parses each word and construes the sentence | against the stored analysis |
| questions on a passage (`passage-mc`) | answers five multiple-choice questions on one passage | fixed answers |
| mark the dependences (`mark`) | marks every dependence in the sentence | against the stored analysis |
| copy word for word (`copy`) | types the passage out | exact, word for word |

Question points are multiple choice. A written exercise or review is drawn by `runEx` in course.js: multiple choice, identify, sort, and the typed answers in the next section. A file still marked as a plan shows the plan screen.

## Data fields of the renderers (18 Oct 2026)

`runEx` draws every type below. One sample of each type is in `test/typed-samples.js`. That file is not listed in `data/exercises/index.js`, and the course does not load it.

Every item has `id`, `set`, `type`, `prompt`, and `explain`. It may have `why`, with `prompt` and `model`. The renderer supplies “Correct” or “Incorrect.” For count, form, divide, transform, mark, and analysis it also shows the student’s answer beside the correct one. The correct column shows only the first accepted answer (`accept[0]`, or the first parse in a list). When another accepted answer still differs after normalization, a line below reads “Also accepted:”. A wrong copy does not show the two texts: it marks the first word that differs. An identify item keeps its present feedback. An item type with no renderer shows “This item type is not yet available.”

`macrons: false` on a count, form, divide, or analysis item means macrons are not tested. Otherwise a macron must be typed. Other accents are ignored. Curly quotes are read as straight quotes. Surrounding and repeated spaces are collapsed. Case is ignored, except in a copy. Hyphens and dashes are treated alike on count, form, divide, and transform. When `accept` is present it is the whole list, and `answer` is not added to it. A copy is compared in Unicode NFC, and paste into the copy box is blocked.

| Type | Fields the checker reads | How it is compared |
|---|---|---|
| count (`count`) | `answer` (a number or a string). `accept` or `answers` may give further answers | exact, after the normalization above. A whole number ignores leading zeros, so `04` and `4` match. Spaces inside the answer are kept, so `1 2` does not match `12` |
| give the form (`form`) | `answer`, or `accept` (a string or a list). `answers` is read when `accept` is absent | exact, after the same normalization. One trailing period is ignored. Any other final punctuation is kept. A form is not read as a number |
| divide into syllables (`divide`) | `answer`, the division, with hyphens | the same normalization, and spaces around a hyphen are removed |
| rewrite (`transform`) | `accept`, a short list, or one string. A single `answer`, or `answers`, is used when `accept` is absent | spacing, capitals, and final punctuation (`.?!;:,` and the ellipsis) are ignored, including a final period inside a closing quotation mark |
| identify in the text (`identify`) | `tokens`; `answer` is one index, or a list of indexes | the stored position. One index is a single click. A list means every word asked for, then Check. This behavior is unchanged |
| mark the dependences (`mark`) | `tokens`; `analysis`, a list of `[from, to]`, indexes into `tokens`. `from` is the word that depends, and `to` is the word it depends on | the set of arrows, in any order |
| parse and construe (`analysis`) | `tokens`; `analysis.parse`, a string or a list of accepted strings for each token; `analysis.arrows`, the same pairs as on a mark item | the first word is the part of speech. Commas, extra spaces, and case are ignored, and the accidents after the part of speech may stand in any order. The arrows are matched as a mark is matched |
| copy word for word (`copy`) | `text`, the passage. A source note, when the passage is not yet entered, is `src` | word for word. Capitals, spelling, and punctuation must match. Whitespace is collapsed, curly quotes are read as straight quotes, and the text is compared in Unicode NFC. A wrong copy marks the first word that differs |

## Build list (approved by Timothy, 17 Oct 2026)

2. **Cumulative review, with spaced reminders.**
   - **Placement and look.** At the end of every Roman-numeral section (after Section I, after II, … after XI), after that section's last item (its review), the homepage shows a full-width bar about half the height of a normal deck or section tile, labeled **"Cumulative Review"**, with a second line giving its range from the beginning of the course through that section, e.g., "The Preliminary Section through Section III." (The course calls its opening part "the Preliminary section" in card text and "Preliminary" in ITEM-LIST.md; this label follows that usage. If Timothy prefers "Preliminaries through Section III," change only the label.) There is no bar after the Preliminary section itself.
   - **Content.** Each bar draws on everything from the beginning of the course through that section: question-point variants and exercise and review items from every deck in that range, mixed together (interleaved), never only one section at a time. A sitting holds about 20 items: first the student's missed items that are due (item 3), then a sample from the whole range, weighted toward the decks studied longest ago, with each section in the range represented. Items from decks the student has not completed are not used. Feedback follows rule 11 of ITEM-LIST.md.
   - **Spacing.** Every item the student answers gets a box in localStorage (a simple Leitner scheme: a wrong answer returns the item to box 1; a right answer moves it up one box; boxes 1–5 fall due after 1, 3, 7, 14, and 30 days). The homepage shows a quiet reminder at the top when items are due (for example, "12 review items are due"), and the bar of the furthest section the student has reached opens them.

3. **Re-ask missed items at the end of a sitting.** In exercise sets, reviews, and the cumulative review, an item answered wrongly is asked once more at the end of the same sitting (in a new option order), and it is recorded as due for the cumulative review whatever the second answer.

5. **Exercise sets for Section V (Construction) and Section VI (correction).** V, the center of syntax, gets its own set: find the subject and the verb, name each agreement and the accidents in which the words agree, say what governs what, and correct an incorrect construction (types `mark`, `mc-marked`, `transform`). 6. **Anchor texts carried through every section.** Three texts recur in every section's exercises with new questions each time, so that the student keeps applying new doctrine to familiar real texts: John Donne's Holy Sonnet X ("Death, be not proud"), the Gettysburg Address, and the opening of the *Aeneid* (I.1–7, with a translation close enough to align phrase by phrase). For example: in I, the signs and the kinds of sentence in them; in II, syllables, stress, and meter; in III, the parts of speech of marked words; in V, agreement and dependence; in VI and VII, licenses, figures, and tropes; in IX, full analysis. Not the Our Father. Translations and texts follow the usual rules (real published translations; the Donne text from a standard edition).
7. **"Why" prompts with model answers.** Some skill items are followed by a short "Why?" prompt: the student writes a sentence, then reveals a model answer and checks himself (no grading), as with the Recitation Tablet. Use them where the reason is the point (why a form is a solecism, why a word is syncategorematic).
8. **Easy-to-hard ordering.** Within each fixed set, order the items from easier to harder (simple English examples, then Latin, then contested or mixed cases), and let the reviews reach the contested cases.
9. **Recitation reminders.** A few days (about three) after a student has recited a deck or a section on the Recitation Tablet, the homepage reminds him to recite it again; the reminder repeats at longer intervals (for example, a week, then a month), using the same localStorage record.

**Evening out answer lengths.** Avoid giving the correct answer away by its length, but never at the cost of clarity. Prefer shortening the correct option or developing a distractor naturally into a real alternative; never pad wrong options, which makes questions confusing (STYLE-GUIDE-CARDS.md rule 28). **Across a set, the correct option may sometimes be the longest, but never always or mostly (Timothy, 18 Oct 2026):** aim for it to be the longest in no more than about a quarter to a third of a set’s multiple-choice items, and check the count before committing. To even out, tighten the correct option or lengthen a wrong option with real, plausible content that keeps it clearly wrong; never add filler.
